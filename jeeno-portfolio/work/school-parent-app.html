School App for Parents · Redesign Case Study

A Big Redesign, Built So the Next Change Is Small

A school app used by parents moved to a new brand. Rather than repaint each screen, the work bound the screens to one token system, made desktop follow mobile, and rewrote the experience for its real reader: a parent.

Role UX/UI Designer
Tool Figma Variables and Components
Platform Mobile and desktop web
Type Company work, details withheld

The product name, logo, company, schools, and all real content are withheld. Every screen on this page was rebuilt for this portfolio with sample data, so it shows the design approach, not the product file.

01 — Overview

A new brand was the reason, not the whole job

Parents use this app to follow school news, grades, payments, health records, and leave. They sign in with their child's account, on a phone or a computer. When the brand changed, the mobile and desktop versions had already drifted apart. A repaint would have carried those problems into the new brand and left the same work waiting for the next change.

02 — Concept of the Change

Four changes that depend on each other

01

A new brand

New screens all use the new theme, while the old one stays so older files keep working.

02

Designed for parents

Warm, plain language for an adult reader, and details that are easy to read and tap.

03

Desktop matches mobile

Mobile is the reference for colors, menu, components, and wording.

04

Tokens across the system

Screens use named tokens instead of raw colors, so a change happens in one place.

03 — What the Audit Found

Two versions of one product, drifting apart

Structure

  • The desktop menu was organized differently from the mobile tab bar.
  • Desktop content started at a different position on each screen.
  • The login screen used raw color values, so it could not follow a theme.

Details

  • Thai text was set in a font with no Thai characters, leaving it to a fallback font.
  • Some screens mixed Thai and English, including labels with both languages in brackets.
  • Search boxes came in two styles, and one had an edge nearly invisible on its background.

06 — Designed for Parents

The account says student. The reader is a parent.

Writing rules

  • Polite, warm, and written for an adult, with no teen slang.
  • Everyday words instead of school office terms.
  • One translation per term, kept in a shared glossary.

What stays as it is

  • A greeting with the student's name looks wrong for a parent, but it is right: it confirms whose records are open.
  • One screen uses one language, with no mixed labels.

08 — Decisions & Trade-offs

What each rule gave, and what it cost

1. Mobile is the source of truth

The two versions had drifted apart, so one became the reference: desktop now follows mobile's menu, components, and words.

Upside

Moving between phone and computer feels like the same product.

Cost

Desktop inherits mobile's open issues too, such as button labels still to be improved.

2. Keep the old theme instead of replacing it

The new brand is its own theme. The old one stays, marked as legacy and closed to new work.

Upside

Older files keep working, and the change carries little risk.

Cost

Two similar themes can be confused, so every new screen must set its theme explicitly.

3. Never edit a shared component in place

One file serves several products. Changes are made on a clone, and additions are approved first.

Upside

A fix for this app cannot quietly break another product.

Cost

Small known issues stay in the shared part, and need a workaround on each screen.

4. Pair two fonts, by language

The brand's English font has no Thai characters, so a matching Thai font now sets Thai text.

Upside

Thai text no longer depends on whatever fallback font appears.

Cost

Until Thai text styles exist, the font has to be set by hand, and the styles are still a proposal.

09 — Where It Stands

What is done, and what still is not

01

Desktop set aligned to mobile

The desktop screens were aligned and the missing ones designed in Figma, and QA found no blocking issues.

02

Known gaps remain

Some illustrations and a gradient cannot follow a theme yet, and a warning icon's contrast needs a new token.

03

No impact numbers to share

This page does not claim results from parents. Its claim is about the structure: what one change now takes.
